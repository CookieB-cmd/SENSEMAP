# SENSEMAP v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first public, mobile-friendly SENSEMAP PWA where visitors can discover places, filter by sensory/accessibility needs, understand a place quickly, and signed-in contributors can submit structured and live reports in Nynorsk or English.

**Architecture:** A React + TypeScript + Vite PWA talks directly to a Supabase PostgreSQL/PostGIS backend for public read data and authenticated contribution writes protected by grants and Row Level Security. External OSM search/discovery is isolated behind Supabase Edge Functions and provider interfaces with caching, so public OSM infrastructure is never a hard dependency and providers can be replaced without changing the UI. Personal sensory preferences remain local to the browser and are translated into structured filters and a personal-fit score client-side.

**Tech Stack:** Node 22 LTS, pnpm, React, TypeScript, Vite, React Router, MapLibre GL JS, OpenFreeMap style source, Supabase JS/Auth/PostgreSQL/PostGIS/Edge Functions, i18next/react-i18next, Zod, Vitest, React Testing Library, Playwright, vite-plugin-pwa.

**Spec:** `docs/superpowers/specs/2026-08-30-sensemap-v0.1-design.md`

## Global Constraints

- Free for everyone. No premium tier, paywall, or advertising.
- Searching, browsing, filtering, and viewing place information require no login.
- Login is required to submit or edit community data and write text comments.
- Sensory preferences are stored locally by default.
- Precise user location is not retained merely to provide nearby results.
- Present concrete environmental attributes and confidence; do not create a universal safety score.
- Multiple independent reports are aggregated so one report cannot define an established place profile.
- Nynorsk (`nn`) and English (`en`) are first-class product languages from the first release.
- No user-facing UI string may be hard-coded outside locale resources.
- OpenStreetMap-derived source data and SENSEMAP community data remain logically separate.
- Live reports have explicit expiry and stop influencing “right now” state after expiry.
- No public contributor activity trail, follower system, likes, or public reputation points.
- Android packaging, images, verified businesses, push notifications, full offline maps, social feeds, AI chat, external crowd feeds, and additional languages are out of v0.1 scope.
- External OSM services must be accessed through replaceable server-side provider boundaries with caching. Public Nominatim must not be used for client-side autocomplete, and public Overpass must not be a production-scale routine viewport dependency.

- [ ] **Step 3: Create the public `nearby_places` RPC/read model**

In `0005_public_read_models.sql`, create a SQL function returning only public place fields and distance:

```sql
create or replace function public.nearby_places(
  p_lat double precision,
  p_lng double precision,
  p_radius_m integer default 5000
)
returns table (
  id uuid,
  name text,
  category text,
  address text,
  latitude double precision,
  longitude double precision,
  distance_m double precision
)
language sql
stable
security invoker
set search_path = public
as $$
  select
    p.id,
    p.name,
    p.category,
    p.address,
    st_y(p.location::geometry),
    st_x(p.location::geometry),
    st_distance(p.location, st_setsrid(st_makepoint(p_lng, p_lat), 4326)::geography)
  from public.places p
  where st_dwithin(p.location, st_setsrid(st_makepoint(p_lng, p_lat), 4326)::geography, p_radius_m)
  order by p.location <-> st_setsrid(st_makepoint(p_lng, p_lat), 4326)::geography
  limit 200;
$$;
```
