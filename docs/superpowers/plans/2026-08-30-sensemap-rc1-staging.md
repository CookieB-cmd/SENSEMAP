# SENSEMAP v0.1.0-rc1 Public Staging Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish `v0.1.0-rc1` as a public Vercel PWA backed by a durable Supabase/PostGIS RC database that accepts real community contributions and preserves them for future production use.

**Architecture:** Keep the existing static Vite/PWA frontend and Supabase backend boundary. Harden the source for a public RC first, merge only after the complete repository release gate passes, then provision a dedicated `eu-north-1` Supabase project from that green `main`. Commit only browser-public deployment values, deploy to Vercel, configure hosted Auth/provider settings outside Git, smoke-test the exact deployed commit, and only then create the immutable `v0.1.0-rc1` tag/release.

**Tech Stack:** Node 22 LTS, pnpm 10.15.0, React 19, TypeScript 5.9, Vite 7, vite-plugin-pwa, React Router, MapLibre GL 5, Supabase/PostgreSQL/PostGIS/Auth/Edge Functions, Deno 2, Vitest, Playwright, Vercel.

**Spec:** `docs/superpowers/specs/2026-08-30-sensemap-rc1-staging-design.md`

## Global Constraints

- Public visitors can search, browse, filter and view without login.
- Community submissions, edits, comments and flags require Supabase authentication.
- Contributor authentication remains email magic-link only for RC1.
- Valid contributions publish immediately and are moderated after publication.
- Personal sensory preferences remain local-first in browser storage.
- Nearby/location inputs must not become a stored user-location history.
- RC contributions are production-intent data and must survive the RC period.
- After public collection begins, never reset the hosted RC database as a normal deployment step.
- OSM-derived place data and SENSEMAP community data remain logically separate.
- Public Nominatim is allowed only for explicit low-volume search behind the server-side cache/provider boundary and must be held to a global outbound budget of at most one cache-miss request per second.
- Public Overpass is not a routine RC1 viewport backend. Discovery must fail closed unless a capacity-appropriate provider is explicitly configured later.
- `SUPABASE_SERVICE_ROLE_KEY`, Supabase secret keys and provider credentials must never enter `VITE_*`, Git, generated browser assets or public runtime configuration.
- Browser-public values (`VITE_SUPABASE_URL`, publishable key, map style URL, RC channel/version) may be committed in `.env.production` because they are delivered to every browser by design; an automated allow-list test must prevent privileged values from being added there.
- Nynorsk and English remain exact localization peers.
- The existing complete release gate remains mandatory for every source/deployment-config commit that can affect the announced RC.
- The immutable tag `v0.1.0-rc1` is created only after the exact deployed commit has passed deployed smoke testing.

### Task 3: Enforce the public Nominatim outbound budget on cache misses

**Files:**

**Interfaces:**
- Consumes: service-role Supabase client already created by `place-search` and the existing DB-backed response cache.
- Produces: database RPC `claim_provider_request_slot(p_provider text, p_interval_ms integer) -> boolean` callable only by `service_role`.
- Produces: `claimProviderRequestSlot(client, provider, intervalMs): Promise<boolean>` in the Edge shared module.
- Rule: cache hits do not consume a slot; a Nominatim cache miss must claim a 1000 ms global slot before the outbound provider request. Failure returns HTTP 429 with `Retry-After: 1` and does not contact the provider.

- [ ] **Step 3: Add the provider-slot migration**

`0010_provider_request_slots.sql` must:

1. create `public.provider_request_slots(provider text primary key, next_allowed_at timestamptz not null)`;
2. enable RLS on the table;
3. revoke table access from `anon` and `authenticated`;
4. create `public.claim_provider_request_slot(text, integer)` as `SECURITY DEFINER SET search_path=public`;
5. validate `p_interval_ms between 0 and 60000`;
6. serialize competing requests with `INSERT ... ON CONFLICT DO NOTHING` followed by `SELECT ... FOR UPDATE`;
7. update `next_allowed_at = clock_timestamp() + (p_interval_ms * interval '1 millisecond')` only when the previous value is due;
8. revoke function execution from `public`, `anon`, and `authenticated`;
9. grant function execution to `service_role`.

Use a local variable and return `true` only for the request that successfully advances the slot.

- [ ] **Step 6: Implement the shared helper and wire place-search**

`providerRateLimit.ts` exposes:

```ts
interface RpcClient {
  rpc(name: string, args: Record<string, unknown>): PromiseLike<{ data: unknown; error: unknown }>
}

export async function claimProviderRequestSlot(
  client: RpcClient,
  provider: string,
  intervalMs: number,
): Promise<boolean> {
  const { data, error } = await client.rpc('claim_provider_request_slot', {
    p_provider: provider,
    p_interval_ms: intervalMs,
  })
  if (error) throw error
  return data === true
}
```

In `place-search/index.ts`, after `readCache(...)` returns no cached value and before `FetchProviderClient.fetchJson(...)`:

```ts
const allowed = await claimProviderRequestSlot(supabase, 'nominatim', 1000)
if (!allowed) {
  return jsonResponse(
    { error: 'Search is temporarily busy. Please retry.' },
    429,
    { 'Retry-After': '1' },
  )
}
```

If the current `jsonResponse` helper does not accept extra headers, extend it in `supabase/functions/_shared/cors.ts` and add a focused Deno test for header merging rather than dropping the `Retry-After` requirement.
